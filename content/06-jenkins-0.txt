## Parts of Jenkins
# c-jkjob | Job and build | Beginner | What to do, and one time of doing it.
@@ user Developer ; card Job ; server Agent ; doc Build #42
= Without it | PROBLEM
The steps live in someone's memory.
= What it is | SOLUTION
A **job** describes work. A **build** is one run of it with a number, a log and a result.
= How it works
Results: success, unstable (tests failed), failure, aborted. The **workspace** is the folder where it runs.
= Real-time example | PRACTICE
Build 41 was green, 42 is red. The difference between them is three commits, so the cause is easy to find.
? One run of a job is a... | plugin | *build | node

# c-jkplugin | Plugins | Beginner | Adding abilities.
@@ user Admin ; box Plugin ; gear Jenkins ; cloud Other tools
= Without them | PROBLEM
Jenkins itself knows little: no Git, no Docker, no chat.
= What they are | SOLUTION
Small packages that add features: Git, Pipeline, Credentials, Kubernetes, JUnit.
= How it works
Install from the plugin manager, restart if needed, and read security advisories.
= Real-time example | PRACTICE
A team had 140 plugins and an update broke half. They now keep 35 and test updates on a copy first.
? More plugins mean... | more speed | *more to maintain | no risk

# c-jknode | Controller, node, executor | Beginner | Who plans and who works.
@@ gear Controller ; queue Queue ; server Node ; card Executor
= Without nodes | PROBLEM
All builds on one machine: slow, and one project's tools break another's.
= What they are | SOLUTION
The **controller** plans, **nodes** (agents) work, an **executor** is one slot on a node.
= How it works
A job asks for a **label** such as `linux && docker`. The queue waits until a matching executor is free.
= Real-time example | PRACTICE
Four nodes with two executors run eight builds at once. A Mac node with the label `mac` builds the phone app.
? A label is used to... | name a build | *choose a node | store a password

# c-jkcred | Credentials and webhooks | Beginner | Keys kept safe, and instant starts.
@@ cloud GitHub ; flag Webhook ; gear Jenkins ; key Credentials
= Without them | PROBLEM
Jenkins asks the code host every minute "anything new?", with a password written in the job.
= What they are | SOLUTION
A **webhook** is a message from the host at each push. **Credentials** are stored encrypted and used by ID.
= How it works
Push, webhook, matching job starts. The job borrows a credential only for the step that needs it.
= Real-time example | PRACTICE
Builds start two seconds after a push instead of up to five minutes later.
? A webhook is sent by... | the tester | *the code host | the database
