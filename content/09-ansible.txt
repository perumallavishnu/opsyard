## Basics
# an-what | What Ansible does | Beginner | One control node, many machines, no agent.
@ c laptop 0 1 Control node
@ i doc 1 0 Inventory
@ a server 2 0 web1
@ b server 2 1 web2
@ d db 2 2 db1
= Twenty servers by hand | PROBLEM
+ a b d
: a ok v1.28
: b warn v1.24
: d err missed
Doing the same steps by SSH leaves each server slightly different. That is **configuration drift**.
= Agentless | SOLUTION
+ c
~ c>a SSH ;; c>b SSH ;; c>d SSH
Ansible connects over SSH (or WinRM / PSRP for Windows), copies small modules, runs them with Python, removes them.
= Inventory
+ i
~ c>i who?
> [web]
> web1 ansible_host=10.0.1.11
> web2 ansible_host=10.0.1.12
> [db]
> db1 ansible_host=10.0.2.11
Cloud inventory plugins can build the list automatically.
= Ad hoc
One module, run once, with no playbook. Ansible's ping logs in and checks Python; it is not a network ping.
~ c>a ping ;; c>b ping
$ ansible web -i hosts.ini -m ansible.builtin.ping
= Idempotent
: a ok no change
: b ok changed
Modules describe a state. Running twice changes nothing the second time.
= Requirements
* c
ansible-core 2.20 and 2.21 need Python 3.12 to 3.14 on the control node, which must be Linux, macOS or WSL.
? Why is a second run safe? | It is blocked | *Modules are idempotent | It uses an agent
^ https://docs.ansible.com/ Ansible documentation

# an-play | Playbooks, tasks and handlers | Beginner | YAML that describes the result.
@ p doc 0 0 Playbook
@ t1 card 1 0 Install
@ t2 card 2 0 Template
@ t3 card 3 0 Service
@ h flag 3 1 Handler
@ s server 4 0 Server
= Play
+ p t1
~ p>t1
> - hosts: web
>   become: true
>   tasks:
>     - name: Install nginx
>       ansible.builtin.apt: { name: nginx, state: present, update_cache: true }
A play maps hosts to tasks. `become` uses sudo.
= Template
+ t2
~ t1>t2
>     - name: Configure
>       ansible.builtin.template: { src: nginx.conf.j2, dest: /etc/nginx/nginx.conf }
>       notify: Reload nginx
Jinja2 templates fill in variables.
= Handler
+ h
~ t2>h only if changed
>   handlers:
>     - name: Reload nginx
>       ansible.builtin.service: { name: nginx, state: reloaded }
Runs once at the end of the play, only when notified.
= Service
Make sure nginx runs now and after every reboot.
+ t3 s
~ t2>t3 ;; t3>s
>     - ansible.builtin.service: { name: nginx, state: started, enabled: true }
= Run
$ ansible-playbook -i hosts.ini site.yml --check --diff
$ ansible-playbook -i hosts.ini site.yml
`--check` predicts; `--diff` shows file changes. Some modules cannot predict fully.
= Avoid shell | PRACTICE
* t1
`command` and `shell` are not idempotent by themselves. Prefer a real module, or add `creates:` and `changed_when:`.
? When does a handler run? | Always | *When a task that changed notified it | First

## Structure
# an-vars | Variables, facts, loops, conditions | Intermediate | Making one playbook fit many hosts.
@ g doc 0 0 group_vars
@ h doc 0 1 host_vars
@ f gauge 1 1 Facts
@ p gear 1 0 Play
@ u server 2 0 Ubuntu
@ r server 2 1 RHEL
= Where values live
+ g h p
~ g>p ;; h>p
`group_vars/web.yml` for a group, `host_vars/web1.yml` for one. Host beats group; `-e` on the command line beats everything.
= Facts
+ f u r
~ u>f ;; r>f ;; f>p
Ansible gathers OS, memory, addresses. Use `ansible_facts['os_family']`.
= Conditions
`when` runs a task only where the expression is true, so one play can serve both families.
~ p>u apt ;; p>r dnf
> when: ansible_facts['os_family'] == 'Debian'
= Loops
* u
> - ansible.builtin.apt: { name: "{{ item }}", state: present }
>   loop: [git, curl, unzip]
For packages, passing the whole list to `name` is faster.
= Register and blocks
* p
`register` keeps a result for later. `block`, `rescue`, `always` work like try, catch, finally.
? Which value wins? | group_vars | host_vars | *-e on the command line

# an-roles | Roles, collections and Vault | Intermediate | Reuse and secrets.
@ p doc 0 0 site.yml
@ r1 folder 1 0 Role: nginx
@ r2 folder 1 1 Role: app
@ g cloud 2 0 Galaxy
@ v key 2 1 Vault
= Role
+ p r1
~ p>r1
$ ansible-galaxy role init nginx
A fixed layout: `tasks/`, `handlers/`, `templates/`, `defaults/`, `vars/`, `meta/`.
= Compose roles
+ r2
~ p>r2
> roles: [nginx, app]
Put values users may change in `defaults/`.
= Collections
+ g
~ g>r1
$ ansible-galaxy collection install -r requirements.yml
Packages of modules and roles. Use full names such as `community.docker.docker_container` and pin versions.
= Vault
+ v
~ v>r2 decrypt
$ ansible-vault encrypt group_vars/prod/vault.yml
$ ansible-playbook site.yml --ask-vault-pass
Set `no_log: true` on tasks that handle secrets.
= Test roles
* r1 r2
`ansible-lint` checks style. **Molecule** runs the role in a container, runs it again to prove idempotence, then verifies.
? Values users should override go in... | vars/ | *defaults/ | handlers/

# an-roll | Rolling updates and scale | Advanced | Changing a fleet without an outage.
@ c gear 0 1 Control node
@ lb router 1 0 Load balancer
@ a server 2 0 web1
@ b server 2 1 web2
@ d server 2 2 web3
= All at once | RISK
+ c a b d
~ !c>a ;; !c>b ;; !c>d
: a err
: b err
: d err
By default Ansible works on 5 hosts in parallel (`forks`), task by task. A bad change reaches all.
= serial
: a warn updating
~ c>a
: b ok
: d ok
> serial: [1, "25%", "100%"]
> max_fail_percentage: 0
One host, then a quarter, then the rest.
= Drain first
+ lb
~ c>lb remove web1 ;; c>a update ;; c>lb add web1
`pre_tasks` with `delegate_to` take the host out of the load balancer; `post_tasks` test and return it.
= Speed
* c
Raise `forks`, enable pipelining, cache facts, use `async` for long tasks.
= At company scale
* c
**AWX** and Red Hat Ansible Automation Platform add a web UI, RBAC, schedules, logs. Event-Driven Ansible reacts to alerts.
= Ansible or Terraform? | PRACTICE
Terraform creates infrastructure and tracks it in state. Ansible configures what runs on it. Many teams use both.
? Which keyword updates hosts in batches? | forks | *serial | async
