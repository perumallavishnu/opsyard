" a Was it 20 or 21 steps?
: s2 err different
Every server is set up by typing. After a year no two are alike. This is **configuration drift**, and such servers are called *snowflakes*.
= Scripts help, a little | PROBLEM
* a
" a The script fails if run twice.
A shell script that creates a user fails the second time. It says *what to do*, not *how it should be*.
= Describe the result | SOLUTION
+ c
~ a>c playbook ;; c>s1 ;; c>s2
: s1 ok same
: s2 ok same
Ansible reads a file that says how servers **should be**, connects over SSH and changes only what differs. Nothing is installed on them except Python.

# c-module | Module and task | Beginner | One job done properly.
@@ user Admin ; cube Module ; server Server ; card Task
= Without it | PROBLEM
Every admin writes their own script to create a user.
= What it is | SOLUTION
A **module** knows one job: packages, files, services, users, clouds. A **task** calls it.
= How it works
Modules check first. Already right: `ok`. Changed: `changed`.
$ ansible web -m ansible.builtin.service -a "name=nginx state=started"
= Real-time example | PRACTICE
Run twice: first time 12 changed, second time 0. That proves the state is right.
? Second run should report... | 12 changed | *0 changed | errors

# c-pb | Playbook and handler | Beginner | The written plan.
@@ user Admin ; doc Playbook ; server Servers ; flag Handler
= Without it | PROBLEM
Commands are lost in the terminal history.
= What it is | SOLUTION
A YAML file: which hosts, which tasks, in which order. A **handler** runs only when something changed.
= How it works
Change the nginx file, notify the handler, reload nginx once at the end.
= Real-time example | PRACTICE
Disaster: a data centre is lost. The playbook sets up 30 new servers in an hour.
? A handler runs... | always | *when notified by a change | first

# c-role | Role, variable, vault | Intermediate | Reuse and secrets.
@@ user Admin ; folder Role ; server Servers ; key Vault
= Without them | PROBLEM
The same 80 tasks copied into ten playbooks, with a password inside.
= What they are | SOLUTION
A **role** is a reusable bundle. **Variables** adapt it. **Vault** encrypts secrets.
= How it works
The first command makes the folder layout of a new role. The second turns a readable file into an encrypted one.
$ ansible-galaxy role init nginx
$ ansible-vault encrypt secrets.yml
= Real-time example | PRACTICE
One `nginx` role serves twelve teams; each sets only its own domain name.
? Vault is for... | speed | *encrypting secrets | logs
