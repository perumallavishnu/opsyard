# curl | Ubuntu, Kali | curl | Network | s
purpose: Sends HTTP and other requests from the terminal and shows exactly what comes back.
where: Testing APIs, health checks in scripts, finding out why a site fails.
$ curl -v https://example.com # request, response and TLS details
$ curl -fsS https://example.com/health # quiet, non-zero exit on HTTP errors
$ curl -o f.tgz -L https://example.com/f.tgz # save, following redirects
risks: Tokens on the command line stay in shell history. Piping a download into a shell runs code you have not read.
guide: Keep secrets in a file or variable. Verify checksums of downloads.
src: https://curl.se/docs/manpage.html

# jq | Ubuntu, Kali | jq | Text and data | s
purpose: Reads, filters and reshapes JSON.
where: Processing output of cloud CLIs, APIs and kubectl.
$ jq . data.json # pretty print
$ jq -r '.items[].name' data.json # one field per line
$ jq '.users | length' data.json # count
risks: Little risk. A wrong filter can give empty output that a script treats as success.
guide: Use `jq -e` in scripts so missing values fail.
src: https://jqlang.org/manual/

# tmux | Ubuntu, Kali | tmux | Shell | s
purpose: Keeps terminal sessions alive after you disconnect, and splits the screen.
where: Long tasks over SSH, pairing on a server.
$ tmux new -s work # new named session
$ tmux attach -t work # return to it
$ tmux ls # list
risks: Anyone with your account can attach to the session.
guide: Detach with Ctrl-b d. Close sessions that hold elevated rights.
src: https://github.com/tmux/tmux/wiki

# htop | Ubuntu, Kali | htop | Monitoring | s
purpose: Interactive view of processes, CPU and memory.
where: Finding what is using a server right now.
$ htop # F6 sorts, F5 tree, F9 sends a signal
$ htop -u www-data # one user
risks: Killing the wrong process causes an outage.
guide: Read the full command line before sending a signal.
src: https://htop.dev/

# strace | Ubuntu, Kali | strace | Debugging | c
purpose: Shows the system calls a program makes.
where: When a program fails with no useful message: missing file, refused connection.
$ strace -f -e trace=file ./app # file access, including children
$ sudo strace -p 1234 -c # summary of a running process
risks: Slows the process a lot. Output can include passwords.
guide: Use briefly in production. Protect the output.
src: https://strace.io/

# lsof | Ubuntu, Kali | lsof | Debugging | s
purpose: Lists open files and sockets and who holds them.
where: "Port already in use", or disk space not freed after deleting a log.
$ sudo lsof -i :8080 # who uses this port
$ sudo lsof +L1 # deleted files still open
risks: Shows other users' activity when run as root.
guide: Filter narrowly; a full listing is slow.
src: https://github.com/lsof-org/lsof

# tcpdump | Ubuntu, Kali | tcpdump | Network | c
purpose: Captures packets on an interface.
where: Proving whether traffic arrives, and in what form.
$ sudo tcpdump -ni any port 5432 -c 50 # fifty packets on one port
$ sudo tcpdump -ni eth0 -w cap.pcap # save for Wireshark
risks: Captures may contain personal data and credentials.
guide: Capture only systems you are allowed to. Filter narrowly, store safely, delete after.
src: https://www.tcpdump.org/manpages/tcpdump.1.html

# wireshark | Ubuntu, Kali | wireshark | Network | c
purpose: Graphical packet analysis with protocol decoding.
where: Understanding handshakes, retransmissions and protocol errors.
$ wireshark cap.pcap # open a capture
$ tshark -r cap.pcap -Y "tcp.analysis.retransmission" # terminal version, filtered
risks: Same privacy risk as tcpdump.
guide: Capture with tcpdump, analyse on your machine as a normal user.
src: https://www.wireshark.org/docs/

# mtr | Ubuntu, Kali | mtr-tiny | Network | s
purpose: Combines ping and traceroute, showing loss per hop.
where: Slow or lossy connections.
$ mtr -rwc 50 example.com # report after 50 rounds
$ mtr -T -P 443 example.com # with TCP to 443
risks: Some routers answer slowly on purpose, which looks like loss.
guide: Loss that continues to the last hop is real; loss at one middle hop usually is not.
src: https://www.bitwizard.nl/mtr/

# iperf3 | Ubuntu, Kali | iperf3 | Network | c
purpose: Measures network throughput between two machines you control.
where: Checking links between servers or zones.
$ iperf3 -s # on the first
$ iperf3 -c server1 -t 10 # on the second
risks: Fills the link and can disturb others; cloud transfer may cost money.
guide: Run in agreed windows and stop the server afterwards.

# ufw | Ubuntu, Kali | ufw | Firewall | c
purpose: Simple front end to the Linux firewall.
where: Single servers that need a few clear rules.
$ sudo ufw allow OpenSSH # do this first
$ sudo ufw enable # turn on
$ sudo ufw status verbose # show rules
risks: Enabling without allowing SSH locks you out. Docker's published ports can bypass ufw.
guide: Allow SSH before enabling. Keep a console open while testing.
src: https://help.ubuntu.com/community/UFW

# aide | Ubuntu, Kali | aide | Defence | c
purpose: Detects changed files by comparing checksums.
where: Servers whose system files should rarely change.
$ sudo aideinit # build the baseline
$ sudo aide --check --config /etc/aide/aide.conf # compare
risks: A baseline made after a break-in hides it. Updates cause noise.
guide: Build on a clean system, store the baseline off the host, refresh after updates.
src: https://aide.github.io/

# trivy | Ubuntu, Kali | | Container security | s
purpose: Scans images, files, IaC and clusters for vulnerabilities, secrets and misconfiguration.
where: CI pipelines and registries. Install from the vendor's repository.
$ trivy image nginx:latest # scan an image
$ trivy fs --scanners vuln,secret . # scan a folder
$ trivy image --severity HIGH,CRITICAL --exit-code 1 app:1 # fail the pipeline

# nmap | Ubuntu, Kali | nmap | Discovery | c

where: Inventory, checking firewall rules, authorised security tests.

$ nmap -sn 10.0.0.0/24 # which hosts are up

# openssl | Ubuntu, Kali | openssl | Cryptography | c
purpose: Works with certificates, keys and TLS connections.
where: Checking expiry, testing TLS, creating test certificates.
$ openssl s_client -connect example.com:443 -servername example.com # inspect a server
$ openssl x509 -in cert.pem -noout -dates # expiry
$ openssl rand -base64 32 # random secret
risks: Private keys left readable. Self-signed certificates used in production.
guide: chmod 600 for keys; use ACME for real certificates.
