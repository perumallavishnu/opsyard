## Parts of Terraform
# c-prov | Provider | Beginner | The translator to each service.
@@ doc Your files ; gear Provider ; cloud Service API ; bucket Registry
= Without it | PROBLEM
You would write different API code for every service.
= What it is | SOLUTION
A plugin that knows one service: aws, azurerm, google, kubernetes, github.
= How it works
> terraform {
>   required_providers { aws = { source = "hashicorp/aws", version = "~> 6.0" } }
> }
`terraform init` downloads it.
= Real-time example | PRACTICE
One project makes the AWS network, the GitHub repository and the DNS record together.
? init downloads... | state | *providers | servers

# c-res | Resource and data source | Beginner | Things to make, and things to look up.
@@ user Engineer ; box Resource ; cloud Cloud ; card Data source
= Without it | PROBLEM
A wiki page says which servers should exist. It is wrong.
= What it is | SOLUTION
A **resource** block describes one thing to manage. A **data** block reads something that exists.
= How it works
> resource "aws_s3_bucket" "docs" { bucket = "acme-docs" }
Others refer to it as `aws_s3_bucket.docs.id`, and Terraform works out the order.
= Real-time example | PRACTICE
A `data` block finds the newest system image, so new servers always start patched.
? data blocks... | create | *read | delete

# c-var | Variable, output, local | Beginner | Making files reusable.
@@ user Engineer ; card Variables ; folder Files ; doc Outputs
= Without them | PROBLEM
Two copies of everything: one with "test", one with "prod".
= What they are | SOLUTION
**Variables** are inputs, **outputs** are results, **locals** are named values inside.
= How it works
Values come from a file, the command line, the environment or a default. Types and validation catch mistakes early.
$ terraform apply -var-file=prod.tfvars
= Real-time example | PRACTICE
One set of files, three var files: small servers in test, large in production.
? Results are given by... | variables | *outputs | providers

# c-state | State | Beginner | Terraform's memory.
@@ gear Terraform ; db State ; cloud Real things ; key Lock
= Without it | PROBLEM
Terraform would not know which server is yours, and would make a second one.
= What it is | SOLUTION
A file that links each block to the real resource.
= How it works
Keep it in shared, encrypted storage with **locking**, so two people cannot apply at once.
= Real-time example | PRACTICE
A laptop with the only state file was lost. The team had to import 60 resources one by one. Since then: remote state.
? Where should team state live? | On a laptop | *In a locked remote backend | In chat

# c-mod | Module | Intermediate | A building block you reuse.
@@ user Team ; box Module ; cloud Networks ; bucket Registry
= Without it | PROBLEM
Eight teams each invent a network, eight different mistakes.
= What it is | SOLUTION
A folder of files with inputs and outputs, used like a function.
= How it works
Give it a version; teams upgrade when ready.
= Real-time example | PRACTICE
The platform team's network module has logging and private subnets built in. A fix reaches all teams with one version change.
? Modules are for... | secrets | *reuse | logs
