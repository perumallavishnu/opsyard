## Getting started
# c-awscli | Account, regions and the AWS CLI | Beginner | Signing in safely and talking to AWS from the terminal.
@@ user You ; laptop AWS CLI ; cloud AWS regions ; key Credentials
= Without it | PROBLEM
Clicking in the web console is fine for looking around, but it cannot be repeated exactly, scripted or reviewed. And if you use the account's first login (the **root user**) for daily work, one stolen password gives away everything.
= What it is | SOLUTION
- An **AWS account** is a container for resources and bills. The email that created it is the **root user**: all-powerful, for emergencies only.
- A **region** is a geographic area, such as `ap-south-1` (Mumbai) or `eu-west-1` (Ireland). Each has several **Availability Zones** (AZs): separate data centres a few kilometres apart.
- The **AWS CLI** is a command-line tool that calls the same APIs as the console.
Most services are regional: a server created in Mumbai does not appear when the console shows Ireland.
= Secure the account first
1. Turn on **MFA** (a second factor) for the root user, then put root aside.
2. Set up **IAM Identity Center** and create a user for yourself with admin rights; sign in with that.
3. Create a **budget alert** so a forgotten resource cannot surprise you.
!! Never create access keys for the root user.
= Install the CLI and sign in
$ aws --version
- aws --version = confirm the CLI (version 2) is installed
$ aws configure sso
- configure sso = set up sign-in through IAM Identity Center; it asks for your start URL and region and saves a **profile**
$ aws sso login --profile dev
- sso login = open the browser to sign in; the CLI receives temporary credentials, valid for hours
- --profile dev = which saved profile to use
= Your first commands
$ aws sts get-caller-identity --profile dev
- sts get-caller-identity = "who am I?": shows your account number and identity. The first thing to run when something says "access denied"
$ aws ec2 describe-regions --query "Regions[].RegionName" --output table
- ec2 describe-regions = list the regions
- --query "Regions[].RegionName" = pick only the names from the answer (JMESPath syntax)
- --output table = print as a table; `json` and `text` also work
Every CLI command follows the same shape: `aws <service> <action> --option value`.
= Environment variables and profiles
$ export AWS_PROFILE=dev
$ export AWS_REGION=ap-south-1
- AWS_PROFILE = use this profile without typing `--profile` each time
- AWS_REGION = the default region for commands
Keep separate profiles for each account (dev, staging, prod), so a command can never reach production by accident.
= Real-time example | PRACTICE
A student creates a free account, leaves root with an access key, and pushes it to a public GitHub repository by mistake. Within an hour bots start expensive servers for crypto mining. Another student sets MFA on root, signs in through Identity Center with temporary credentials, and sets a 10-dollar budget alert: there are no long-lived keys to leak.
? What should you use the root user for? | Daily work | *Only rare account tasks, with MFA | Running servers

## Identity and security services
# c-iam | IAM: who may do what | Beginner | The service every other service asks first.
@@ user Employee ; gate IAM ; db Company data ; doc Policy
= If IAM did not exist | PROBLEM
" a I just wanted to look.
Everyone would share one all-powerful login. A trainee could delete the database by mistake, and nobody could tell who did it. One leaked password would mean losing everything.
= What it is | SOLUTION
**Identity and Access Management** checks every single AWS request: **who** are you, and are you **allowed** to do this? It has no extra charge.
| Part | Meaning |
| User | One person or program with long-term credentials (avoid for people; use Identity Center) |
| Group | A set of users, for example Developers |
| Role | A set of permissions that a trusted person, service or server can take on **temporarily** |
| Policy | A JSON document that allows or denies actions on resources |
Everything is **denied** until a policy allows it, and an explicit **deny** always wins.
= Read a policy
> {
>   "Version": "2012-10-17",
>   "Statement": [{
>     "Effect": "Allow",
>     "Action": ["s3:GetObject"],
>     "Resource": "arn:aws:s3:::acme-docs/*"
>   }]
> }
- Version = the policy language version; always this date
- Effect = Allow or Deny
- Action = which API calls; `s3:GetObject` means "download an object"
- Resource = which things, by **ARN** (Amazon Resource Name); `/*` = every object in the bucket
A **Condition** block can add rules such as "only from our office IP" or "only with MFA".
= Roles: no stored passwords
A web server on EC2 needs to read that bucket. Instead of putting keys on it, you attach a **role** with the policy above. The server receives temporary credentials automatically, renewed every hour.
$ aws iam create-role --role-name web-reader --assume-role-policy-document file://trust.json
- create-role = make a role
- --assume-role-policy-document = the **trust policy**: who may take on this role (here, the EC2 service)
- file://trust.json = read the JSON from a local file
$ aws iam attach-role-policy --role-name web-reader --policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess
- attach-role-policy = give the role a policy; here an AWS-managed read-only one
= Check what is allowed
$ aws iam simulate-principal-policy --policy-source-arn arn:aws:iam::111122223333:role/web-reader --action-names s3:DeleteObject
- simulate-principal-policy = ask IAM "would this identity be allowed this action?" without doing it
**IAM Access Analyzer** finds resources shared outside your account and suggests tighter policies from real usage.
= Real-time example | PRACTICE
A shop has three groups: Developers may change test servers, Finance may read bills, Support may read orders. The web servers use a **role** that can read one bucket. When an employee leaves, one account is disabled, and no password stored on any server has to change.
= Rules to keep | RISK
- MFA on the root user, and no root access keys.
- People sign in through Identity Center; programs use roles.
- Give the least permission that works, then tighten it with Access Analyzer.
- Never put access keys in code or images.
? A server needs to read a bucket. Give it... | the root password | *a role | a user's keys
^ https://docs.aws.amazon.com/IAM/latest/UserGuide/introduction.html IAM User Guide

# c-kms | KMS and Secrets Manager | Intermediate | Locking data, and keeping passwords out of code.
@@ server App ; key KMS / Secrets ; db Encrypted data ; doc Audit log
= Without it | PROBLEM
Database passwords sit in code and configuration files, copied to every laptop. A stolen disk or backup can be read by anyone who finds it.
= What they are | SOLUTION
- **KMS** (Key Management Service) creates and guards encryption keys. The key material never leaves KMS unencrypted; you ask KMS to encrypt or decrypt, and IAM decides who may.
- **Secrets Manager** stores secrets such as database passwords and API keys, and can **rotate** them automatically.
- **Systems Manager Parameter Store** is a simpler, cheaper place for settings and secrets without rotation.
Most AWS storage services (S3, EBS, RDS) encrypt with KMS keys at the tick of a box.
= Store and read a secret
$ aws secretsmanager create-secret --name prod/shop/db --secret-string '{"user":"shop","password":"S3cure!"}'
- create-secret = store a new secret
- --name prod/shop/db = a path-like name, which makes permissions by prefix easy
- --secret-string = the value, here JSON with two fields
$ aws secretsmanager get-secret-value --secret-id prod/shop/db --query SecretString --output text
- get-secret-value = read it (the caller needs permission)
- --query SecretString --output text = print only the value
Applications call the same API at start-up with their role; nothing secret is in the code or image.
= Encrypt with your own key
$ aws kms create-key --description "Patient records"
- create-key = a customer-managed key; you control its policy and can disable it
$ aws kms encrypt --key-id alias/patients --plaintext fileb://note.txt
- encrypt = KMS returns encrypted bytes; only callers allowed by the key policy can decrypt
- fileb:// = read the file as raw bytes
Every use of a key is recorded in **CloudTrail**: who decrypted what, and when.
= Real-time example | PRACTICE
A clinic encrypts its patient database with its own KMS key. When a contractor leaves, their right to use the key is removed. Copies of the data they might have taken are unreadable without the key, and CloudTrail shows every decryption made while they had access.
? Where should a database password live? | In the code | *Secrets Manager | In a wiki
^ https://docs.aws.amazon.com/secretsmanager/latest/userguide/intro.html Secrets Manager User Guide

# c-ec2 | EC2: virtual servers | Beginner | A computer you rent.
@@ user Developer ; server EC2 instance ; team Visitors ; layer AMI
= Without it | PROBLEM
" a I need a server today, for a week.
You would have to buy a machine, wait weeks for delivery, install it, find room for it, and keep paying after the project ends.
= What it is | SOLUTION
**Elastic Compute Cloud** rents you virtual servers, called **instances**, with the CPU, memory and operating system you choose, billed per second while they run.
| Part | Meaning |
| AMI | Amazon Machine Image: the starting disk (Ubuntu, Amazon Linux, Windows, or your own) |
| Instance type | The size: `t4g.small` = family t (burstable), generation 4, g = Graviton (ARM), size small |
| EBS volume | The instance's network disk |
| Security group | Its firewall |
| Key pair / Session Manager | How you log in |
| User data | A script that runs on first boot |
= Launch an instance
$ aws ec2 run-instances --image-id ami-0abc123 --instance-type t4g.small --subnet-id subnet-0a1 --security-group-ids sg-0b2 --iam-instance-profile Name=web-role --count 1 --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=web-1}]'
- run-instances = start new instances
- --image-id = the AMI to start from
- --instance-type = the size
- --subnet-id = which network (and so which Availability Zone)
- --security-group-ids = which firewall rules apply
- --iam-instance-profile Name=web-role = attach a role, so the server needs no keys
- --count 1 = how many
- --tag-specifications = add a Name tag, shown in the console
= Connect and manage
$ aws ssm start-session --target i-0123456789abcdef0
- ssm start-session = a shell on the instance through Session Manager: no open SSH port, no keys, every session logged
$ aws ec2 stop-instances --instance-ids i-0123456789abcdef0
- stop-instances = shut it down; you stop paying for compute but still pay for its disk
$ aws ec2 terminate-instances --instance-ids i-0123456789abcdef0
- terminate-instances = delete it; its root disk is deleted too by default
= Pricing options
| Option | Good for |
| On-Demand | Anything, no commitment |
| Savings Plans / Reserved | Steady use for 1 or 3 years, much cheaper |
| Spot | Interruptible work (batch, CI), up to about 90% cheaper |
= Real-time example | PRACTICE
A school runs its exam portal on two instances. In exam week an Auto Scaling group starts six more; afterwards it stops them. They pay for the extra servers only during that week.
= When not to use it | RISK
With EC2 you patch the operating system, watch the disk and handle failures yourself. For short tasks use **Lambda**; for containers, **Fargate**; for a simple web app, **App Runner** or Beanstalk.
? What is an AMI? | A firewall | *A starting disk image | A price

# c-asg | Auto Scaling | Beginner | The right number of servers, all the time.
@@ team Visitors ; gear Auto Scaling ; server Servers ; gauge CloudWatch
= Without it | PROBLEM
At 8 p.m. traffic triples. Someone has to notice and add servers, or users see errors. At midnight someone must remove them again, or the company pays for idle machines. And a crashed server stays crashed until someone replaces it.
= What it is | SOLUTION
An **Auto Scaling group** (ASG) keeps the number of EC2 instances between a **minimum** and a **maximum**:
- it **replaces** instances that fail health checks;
- it **adds** instances when demand rises and **removes** them when it falls;
- it spreads instances across Availability Zones.
A **launch template** describes what to start: AMI, instance type, security groups, role, user data.
= Create a group
$ aws autoscaling create-auto-scaling-group --auto-scaling-group-name web --launch-template LaunchTemplateName=web,Version='$Latest' --min-size 2 --max-size 10 --desired-capacity 2 --vpc-zone-identifier "subnet-0a1,subnet-0b2" --target-group-arns arn:aws:elasticloadbalancing:...:targetgroup/web/abc --health-check-type ELB
- --launch-template … Version='$Latest' = what to start, using the newest template version
- --min-size 2 --max-size 10 = never fewer than 2, never more than 10
- --desired-capacity 2 = start with 2
- --vpc-zone-identifier = subnets in different zones to spread across
- --target-group-arns = register new instances with the load balancer automatically
- --health-check-type ELB = replace instances the load balancer considers unhealthy
= Scale on a target
$ aws autoscaling put-scaling-policy --auto-scaling-group-name web --policy-name cpu50 --policy-type TargetTrackingScaling --target-tracking-configuration '{"PredefinedMetricSpecification":{"PredefinedMetricType":"ASGAverageCPUUtilization"},"TargetValue":50}'
- TargetTrackingScaling = keep a metric near a target, like a thermostat
- ASGAverageCPUUtilization … 50 = add or remove instances to keep average CPU around 50%
**Scheduled** scaling handles known peaks ("at 7 p.m. set desired to 8"); **predictive** scaling learns daily patterns.
= Update without downtime
$ aws autoscaling start-instance-refresh --auto-scaling-group-name web
- start-instance-refresh = replace instances gradually with the latest launch template, keeping a healthy minimum
= Real-time example | PRACTICE
A food delivery company runs 4 servers in the afternoon, 20 at dinner time and 4 again after midnight, without anyone touching it. One night a server's disk fails; the group replaces it within minutes.
? What replaces a broken instance? | You, by hand | *The Auto Scaling group | S3
^ https://docs.aws.amazon.com/autoscaling/ec2/userguide/what-is-amazon-ec2-auto-scaling.html EC2 Auto Scaling User Guide

# c-elb | Elastic Load Balancing | Beginner | One address, many servers.
@@ team Visitors ; router Load balancer ; server Server 1 ; server Server 2
= Without it | PROBLEM
All visitors go to one server. It is overloaded at peak times, and when it fails, the site is gone. Updating it means downtime.
= What it is | SOLUTION
A load balancer has one stable address, receives every request and passes it to a **healthy** target.
| Type | Works at | Use for |
| ALB (Application) | HTTP/HTTPS | Websites and APIs; route by path or host name |
| NLB (Network) | TCP/UDP/TLS | Very high rates, fixed IP addresses, non-HTTP |
| GWLB (Gateway) | Network packets | Firewalls and inspection appliances |
= How an ALB is put together
- A **listener** waits on a port (443) with a TLS certificate from **ACM** (AWS Certificate Manager, free).
- **Rules** decide where requests go: `/api/*` to one target group, everything else to another.
- A **target group** is a set of targets (instances, IPs, Lambda functions) with a **health check**.
= Health checks
> Path: /health   Interval: 15 s   Healthy after: 3 passes   Unhealthy after: 2 failures
- Path = which URL the load balancer calls on each target
- Interval = how often
- Healthy / Unhealthy thresholds = how many results in a row change the state
$ aws elbv2 describe-target-health --target-group-arn arn:aws:elasticloadbalancing:...:targetgroup/web/abc
- describe-target-health = which targets are healthy, and why not ("Health checks failed with these codes: 502")
= Real-time example | PRACTICE
A news site's ALB sends `/api/*` to one group of servers and everything else to another. During a release, servers are updated one at a time: each is taken out of its target group, updated, checked and put back. Readers never see an error.
? What does a health check do? | Encrypts | *Finds targets that must not get traffic | Scales the database
^ https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html ALB User Guide

# c-lambda | Lambda: code without servers | Intermediate | Run a function when something happens.
@@ user User ; small Lambda ; db Result ; flag Event
= Without it | PROBLEM
A server runs 24 hours a day to resize the ten photos users upload. You pay for the whole day, patch its operating system, and it still cannot cope when 10,000 photos arrive at once.
= What it is | SOLUTION
**Lambda** runs your **function** when an **event** arrives, and bills per request and per millisecond of run time. There is no server to manage, and many events run in parallel automatically.
- Events: an upload to S3, an HTTP request through API Gateway or a function URL, a message in SQS, a schedule from EventBridge, and many more.
- Limits: up to 15 minutes per run, up to 10 GB of memory (CPU grows with memory).
= A function
> export const handler = async (event) => {
>   const key = event.Records[0].s3.object.key;
>   console.log('New upload', key);
>   return { ok: true };
> };
- handler = the function Lambda calls
- event = details of what happened; here the S3 upload, including the object's key
- console.log = goes to CloudWatch Logs automatically
= Deploy and call it
$ zip fn.zip index.mjs
$ aws lambda create-function --function-name resize --runtime nodejs22.x --handler index.handler --zip-file fileb://fn.zip --role arn:aws:iam::111122223333:role/resize-role
- --runtime nodejs22.x = the language and version
- --handler index.handler = file `index`, exported function `handler`
- --zip-file fileb://fn.zip = the code
- --role = the role whose permissions the function has
$ aws lambda invoke --function-name resize --payload '{"test":1}' --cli-binary-format raw-in-base64-out out.json
- invoke = run it once with a test event; the result is written to out.json
= Cold starts
When a function has not run recently, Lambda must start a new environment first: a **cold start** of tens to hundreds of milliseconds. Usually fine; for strict latency use **provisioned concurrency** or **SnapStart**.
= Real-time example | PRACTICE
A travel site: each uploaded photo triggers a function that makes three sizes and saves them back to S3. On a quiet day the bill is a few cents; on a busy holiday it handles thousands of uploads a minute without any change.
= When not to use it | RISK
Jobs longer than 15 minutes, steady heavy traffic all day, or special hardware (GPUs) are often cheaper or simpler on containers.
? Longest single run? | 1 minute | *15 minutes | 1 day
^ https://docs.aws.amazon.com/lambda/latest/dg/welcome.html Lambda Developer Guide

## Storage services
# c-s3 | S3: object storage | Beginner | Files of any amount, reachable by name.
@@ user User ; bucket S3 bucket ; doc Files ; box Cheaper classes
= Without it | PROBLEM
Uploaded photos fill the web server's disk. If the server dies, the photos are gone. A second server cannot see them, and buying bigger disks never ends.
= What it is | SOLUTION
**Simple Storage Service** stores **objects** (a file plus metadata) in **buckets**. There is no folder tree and no size limit for the bucket; each object can be up to 5 TB.
- Each object has a **key**, its full name, such as `2026/invoices/inv-7.pdf`. The `/` only looks like folders.
- S3 is designed for 99.999999999% (eleven nines) durability by keeping copies across several Availability Zones.
- Bucket names are global: no two AWS accounts can have the same bucket name.
= Work with the CLI
$ aws s3 mb s3://acme-docs-2026
- s3 mb = "make bucket"
$ aws s3 cp inv-7.pdf s3://acme-docs-2026/2026/invoices/
- s3 cp = copy a local file to S3 (or back, if you swap the two)
$ aws s3 ls s3://acme-docs-2026/2026/ --recursive --human-readable
- s3 ls = list objects; --recursive = everything under that prefix; --human-readable = sizes in KB/MB
$ aws s3 sync ./site s3://acme-site --delete
- s3 sync = copy only new or changed files
- --delete = also remove objects that no longer exist locally
$ aws s3 presign s3://acme-docs-2026/2026/invoices/inv-7.pdf --expires-in 3600
- s3 presign = a temporary link anyone can use to download this one object, valid for an hour
= Versioning, lifecycle and classes
- **Versioning** keeps every old version of an object, so an overwrite or delete can be undone.
- **Lifecycle rules** move objects to cheaper **storage classes** after some days, or delete them.
| Class | For |
| Standard | Frequently used data |
| Intelligent-Tiering | Unknown patterns; moves objects automatically |
| Standard-IA | Rarely read, but needed quickly |
| Glacier Instant / Flexible / Deep Archive | Archives; cheaper, slower to retrieve |
$ aws s3api put-bucket-versioning --bucket acme-docs-2026 --versioning-configuration Status=Enabled
- s3api = the lower-level commands with every option; here turn on versioning
= Real-time example | PRACTICE

# c-vpc | VPC: your private network | Beginner | Walls and doors around your servers.
@@ cloud Internet ; gate VPC ; server Private servers ; router Subnets
= Without it | PROBLEM
Your database would sit on a network where anyone on the internet can try every port, all day.
= What it is | SOLUTION
A **Virtual Private Cloud** is your own isolated network in AWS, with your own private address range, such as `10.0.0.0/16` (65,536 addresses). You decide what can come in and what can go out.
| Part | Job |
| Subnet | A slice of the VPC in **one** Availability Zone, such as `10.0.1.0/24` |
| Route table | Rules that say where traffic from a subnet goes |
| Internet gateway | The door between the VPC and the internet |
| NAT gateway | Lets private servers reach out (for updates) without being reachable from outside |
| Security group | Firewall attached to each resource |
| Network ACL | Optional firewall for a whole subnet |

= Public and private subnets

- A **private** subnet has no such route; its outgoing traffic goes through the NAT gateway. Put application servers and databases here.
Use at least two Availability Zones, each with a public and a private subnet, so losing one data centre does not stop the system.

$ aws ec2 create-route --route-table-id rtb-0123 --destination-cidr-block 0.0.0.0/0 --gateway-id igw-0def

# c-sg | Security groups | Beginner | The firewall on every server.
@@ cloud Anyone ; shield Security group ; db Database ; server App
= Without it | PROBLEM
Robots scan the whole internet all day long. An open database or SSH port is found and attacked within hours of being created.
= What it is | SOLUTION
A **security group** is a firewall attached to a resource (an instance, a load balancer, a database). It is a list of **allow** rules: protocol, port and source. Anything not allowed is refused.
- It is **stateful**: if a request is allowed in, its answer may go out automatically.
- There are no deny rules; a resource can have several security groups.
- By default, all outgoing traffic is allowed.
= Rules that point at other groups
The source of a rule can be **another security group** instead of an address:
| Group | Inbound rule | From |
| web-sg (load balancer) | TCP 443 | 0.0.0.0/0 (anyone) |
| app-sg | TCP 8080 | web-sg |
| db-sg | TCP 5432 | app-sg |
"Only members of app-sg may reach the database", however many app servers there are and whatever their addresses.
= With the CLI
$ aws ec2 create-security-group --group-name db-sg --description "Database" --vpc-id vpc-0abc
- create-security-group = a new, empty group (no inbound allowed yet)
$ aws ec2 authorize-security-group-ingress --group-id sg-0db --protocol tcp --port 5432 --source-group sg-0app
- authorize-security-group-ingress = add an inbound rule
- --protocol tcp --port 5432 = PostgreSQL's port
- --source-group sg-0app = only from resources in the app group
$ aws ec2 describe-security-group-rules --filters Name=group-id,Values=sg-0db
- describe-security-group-rules = list the rules of a group
= Real-time example | PRACTICE
: c ok 5432 from app only
Web: 443 from anywhere. App: 8080 from the web group. Database: 5432 from the app group. When an Auto Scaling group adds ten app servers at dinner time, they can reach the database at once, and nothing else can.
!! Never allow `0.0.0.0/0` on SSH (22), RDP (3389) or database ports. Use Session Manager instead of SSH.
? Best source for the database rule? | 0.0.0.0/0 | *The app's security group | Your home IP

# c-rds | RDS and Aurora | Beginner | A relational database someone else looks after.

= Without it | PROBLEM

# c-dynamo | DynamoDB and ElastiCache | Intermediate | Very fast lookups by key.
@@ server App ; db DynamoDB ; small Cache ; team Users
= Without them | PROBLEM
Millions of users each read their own shopping cart many times a minute. One relational database becomes the bottleneck, and adding more power to it gets very expensive.
= What they are | SOLUTION
- **DynamoDB** is a fully managed key-value and document database. It answers in single-digit milliseconds at any scale, with no servers or versions to manage.
- **ElastiCache** keeps frequently used data in memory (Valkey, Redis OSS or Memcached) in front of a slower database.
= DynamoDB keys
- The **partition key** decides which partition stores an item; choose one with many different values (`userId`), so load spreads evenly.
- An optional **sort key** orders items with the same partition key (`orderDate`), allowing ranges such as "this user's orders in November".
- Design tables from the **questions you will ask**, not from entities as in SQL.
$ aws dynamodb put-item --table-name carts --item '{"userId":{"S":"u42"},"items":{"N":"3"}}'
- put-item = write one item
- {"S":"u42"} = a value of type String; {"N":"3"} = a Number
$ aws dynamodb get-item --table-name carts --key '{"userId":{"S":"u42"}}'
- get-item --key = read one item by its key, the fastest kind of request
= Caching
**Cache-aside** is the common pattern: the app looks in the cache first; on a miss it reads the database and stores the answer in the cache with an expiry time (TTL). Popular answers are then served from memory.
= Real-time example | PRACTICE
A mobile game keeps each player's state in DynamoDB, keyed by player ID, and the top-100 leaderboard in a Valkey sorted set in ElastiCache. During a tournament, traffic grows twentyfold without any change.

# c-sqs | SQS, SNS and EventBridge | Beginner | Let parts talk without waiting for each other.
@@ server Shop ; queue SQS queue ; gear Worker ; bucket Dead letters
= Without it | PROBLEM
The shop calls the email service directly after each order. When email is slow, paying is slow. When email is down, nobody can pay. One weak part takes the whole system with it.
= What they are | SOLUTION
| Service | Pattern |
| SQS (Simple Queue Service) | A queue: messages wait until a worker takes them, one worker per message |
| SNS (Simple Notification Service) | Publish and subscribe: one message is copied to many receivers |
| EventBridge | An event bus: routes events by rules, also from AWS services and SaaS tools |
The shop only puts a message in the queue and answers the buyer at once. Email workers process messages at their own pace.
= Send and receive with SQS
$ aws sqs send-message --queue-url https://sqs.ap-south-1.amazonaws.com/111122223333/orders --message-body '{"orderId":1009}'
- send-message = put a message in the queue
$ aws sqs receive-message --queue-url https://sqs…/orders --wait-time-seconds 20
- receive-message = take up to 10 messages
- --wait-time-seconds 20 = long polling: wait up to 20 seconds for a message instead of returning empty at once
A received message becomes invisible to other workers for the **visibility timeout**. The worker must **delete** it after success; otherwise it reappears and is tried again.
$ aws sqs delete-message --queue-url https://sqs…/orders --receipt-handle AQEB…
= Failures and dead letters
After a set number of failed attempts (`maxReceiveCount`), SQS moves a message to a **dead-letter queue** (DLQ), so one bad message does not block the others. Someone inspects the DLQ and replays messages once the bug is fixed.
**FIFO** queues keep exact order and remove duplicates, at lower throughput; standard queues deliver at least once, so workers must handle a message arriving twice.
= Real-time example | PRACTICE
On sale day 50,000 orders arrive in an hour. The queue holds them all; workers send confirmation emails steadily and finish by lunch. Three malformed messages land in the DLQ, are fixed and replayed. No order is lost.
